# Atlas private runtime — implementation v0.1

状态：**Owner 已确认 PR #13 部署后的 Claude 问答、私人候选生成以及刷新后恢复对话和候选通过验收**。本分支继续改进工作台阅读、会话管理与发送反馈，合并和线上代码更新仍须 Owner 确认。更新方式见 [UPDATE.md](UPDATE.md)。此目录与公开 Pages 阅读网站分离，不属于 Personal OS 主应用；仍没有 GitHub 写入或正式发布接口。

受环境网络限制时，[GitHub D1 首次接入](GITHUB_SETUP.md) 已在 Owner 配置 Environment Secrets、审阅合并并手动启动后成功运行。[Worker 首次创建流程](WORKER_SETUP.md) 仅负责初次创建；已接入的线上 Worker 使用独立的 [代码更新流程](UPDATE.md)，不随普通推送部署。

## 已实现的边界

- Worker 对工作台和所有 API 校验 Access JWT 的签名、RS256、固定 issuer、audience、有效期及唯一 Owner 邮箱。邮箱在私有配置中；不接受客户端传入 Owner，不提供开发鉴权绕过。
- 工作台与 API 同源。API 拒绝跨站来源；写操作还要求准确 Origin、JSON 和自定义请求头。所有响应禁止公共缓存；工作台使用 CSP、经清洗的 Markdown 渲染和独立登录。没有公开静态资源路由绕过 Worker 校验。
- D1 保存会话、消息、引用版本、私人候选、来源链、请求状态与用量。模型输出不能创建批准、执行工具或取得部署凭据。
- 相同请求 ID 和输入重发返回已保存结果；不重复调用模型。并发会话锁、带约束的事务提交和调用前用量预留，防止旧请求覆盖新状态。超时/未知调用保留预留额度，不自动重放。会话读取时将失去有效租约的处理中请求标为结果未知，允许明确发起新的尝试。
- 新知识自动成为私人候选，状态为待查证。模型不得自称已完成外部检索；本阶段没有网页研究工具或真实发布接口。
- 真实模型需要显式配置 provider、model、密钥和每日调用/token 上限。未配置时只检索真实站内内容；不伪造模型讲解。

## 来源与及时同步

正常站点构建现在同时生成：

- `knowledge-manifest.json`：构建提交、契约摘要、内容地址及数量。
- `knowledge-index.<SHA-256>.json`：完整 Markdown、全部渲染章节（包括未注册 Topic 的深层标题）、Topic/别名、导航与关系。它是派生数据，不能独立编辑。

同步固定读取 Atlas 的公开域名和唯一仓库，验证摘要以及对应 main 提交成功完成 Pages 工作流的 **deploy job**。仓库提交、实际线上版本、索引版本分别记录。新快照完整验证后事务切换；失败保留旧索引、明确标记滞后，并暂停模型调用，只允许带版本说明的既有内容检索。

从公开文章传入的阅读上下文先按快照校验，再将当前章节加入检索，因此“解释这一段”也能引用对应原文；明确的关键词命中仍有更高权重。

代码模板支持每五分钟 Cron；当前已接入的 Worker 保持 Cron 关闭，使用 **新提问/检索前核对 + 手动同步**，检查结果缓存最多一分钟；手动同步立即核对。所有来源的提交都纳入，不限于 Agent 提交。没有宣称零延迟。

这是对原先“部署事件通知 + 兜底轮询”的首期收敛：先避免增加公开 webhook 和额外服务凭据，牺牲后台事件即时性，保留使用时核对。部署事件通知在真实环境稳定后添加；不改变知识身份或来源规则。只有成功 main 发布可激活；临时分支预览不能冒充线上正式知识。

当前单份快照最多 1 MB，适合现有规模；超过时拒绝导入并保留旧版。增长后按版本化契约改为分块索引/存储，无需改变 Topic ID。旧快照不自动清理，需结合实际保留策略处理。

## 本地检查（不需要账号或 API key）

在仓库根目录：

```sh
python -m pip install -r requirements-dev.txt
npm ci --ignore-scripts
python build.py
npm ci --ignore-scripts --prefix agent/runtime
npm run build --prefix agent/runtime
npm test --prefix agent/runtime
```

`build` 只运行 Wrangler `--dry-run`，产物在 `.preview/private-worker/`，不会创建或部署 Worker。集成测试用临时 RSA 签名密钥、禁止真实外网的 HTTP mocks、真实 workerd 和临时 D1；模型、GitHub 和 Access 网络交互均模拟，不进行真实计费或登录。UI 测试还验证刷新后从 D1 恢复会话、文本转义和网页阅读上下文交接。

SQL migrations 追加为 `0002_private_runtime.sql`。本地迁移演练可从本目录执行：

```sh
WRANGLER_SEND_METRICS=false npx --no-install wrangler d1 migrations apply DB --local --config wrangler.jsonc
```

不要把模板里的全零 database ID 当成真实资源。真实配置应复制到忽略的 `wrangler.local.jsonc`，按照 [DEPLOYMENT.md](DEPLOYMENT.md) 接入账号。

## API 与数据范围

所有入口均须通过 Owner JWT；POST/PATCH/DELETE 还要求同源请求头。

| 入口 | 作用 |
| --- | --- |
| `GET /` | 私人工作台，包含受 CSP 限制的交互代码 |
| `GET /api/status` | 身份已核验、三个版本、同步状态、模型是否配置及当日用量 |
| `POST /api/sync` | 从固定可信来源核对内容；不接受用户上传索引 |
| `POST /api/search` | 按已发布快照查文章/章节，返回稳定链接 |
| `GET/POST /api/sessions` | 分页会话列表 / 创建会话 |
| `GET /api/sessions/:id` | 本人会话、消息、候选和请求状态 |
| `PATCH /api/sessions/:id` | 修改本人会话名称（1–80 个 Unicode 码点）和/或布尔置顶状态；保留其他 summary 元数据 |
| `POST /api/sessions/:id/messages` | 检索、可选模型讲解、自动候选和私有保存 |
| `GET /api/sessions/:id/export` | 本次会话与候选/证据的 JSON 导出，不包含 Secrets |
| `DELETE /api/sessions/:id` | 删除会话、消息、候选、关联和请求；进行中的请求阻止删除 |

删除会话会从当前 D1 数据库直接移除会话、消息、关联的未入库候选、候选来源关联以及请求记录；保留独立提案审计、最小来源指针和用量记录，不会删除已发布文章或公开 Git 历史；不是全账户即时抹除。保留周期、备份窗口、完全清理和恢复演练须在真实账号上线前决定。参见上级 `db/README.md`。

工作上下文最多使用最近八条历史消息和有限候选目录；超过输入字节预算时先移除旧消息和候选目录，再收缩低排名检索片段，保留本次问题和最相关原文。消息保存来源版本，新检索优先于旧聊天。尚未实现长期偏好记忆或会话压缩。HTTP 模型调用有超时，未完成请求不会自动重新计费；这不是发布阶段的持久 Workflows 实现。

## 工作台阅读与交互

- 会话列表使用手动名称；未命名时显示首条提问的前 40 个字符。名称来自 `sessions.summary_json.title`，属于展示元数据，不送入模型上下文。改名保留其他 JSON 对象字段，无须追加数据库迁移。旧会话自动兼容。
- 点击发送同步显示提问、清空输入、显示沿原站标志两条椭圆轨迹运动的流星。等待期间可写下一条问题；回答返回不覆盖该草稿。同一请求 ID 不自动重试模型调用；失败后先核对结果，明确的新尝试才可能重新计费。
- 助手与候选正文使用本地打包的 Marked + DOMPurify。支持标题、列表、引用、表格与代码块；原始 HTML 转义，图片显示替代文字，仅允许 HTTP(S) 链接，不加载模型提供的远程图片、脚本、样式或组件。用户消息始终按纯文本处理。暂不提供数学排版、语法高亮或逐 token 流式回答。
- 候选卡片的 Domain/目标文章来自已保存 `placement_json`，通过当前有效知识快照解析名称和 canonical URL。`placement_view` 是读取时生成的视图，不回写候选或复制权威内容；未知 ID、归属不匹配及来源版本变化明确提示。当前候选协议未分配 Topic，文章中的已有 Topic 只作为归类参考展示，不宣称已分配。
- 主体为固定输入框和独立对话滚动区。会话历史/候选均可收起；窄屏使用侧栏抽屉，提供焦点管理和 Escape 关闭。深色沿用浅 Tiffany blue；减少动态效果设置下停用动画。
- `build:client` 将浏览器依赖打包到忽略的 `.preview/private-client/workbench-client.js`；`build` 和 `build:stage` 自动先构建它。Worker 更新仍是原有三个 Text modules，不引入 CDN 或独立公开资源入口。

本地视觉预览（全部为模拟数据，不访问真实模型、私有 D1 或生产账号）：

```sh
# 完成上面的本地 build 后
node agent/runtime/scripts/preview-workbench.js
```

输出 `.preview/workbench-ui/index.html`。该文件的模拟 API 仅用于视觉检查，不属于 Worker 构建或发布产物。真实会话/候选仍由认证后的同源 D1 API 恢复。


## 删除对话的产品规则

- 每条会话的“⋯”菜单均可打开删除确认；左侧底部保留当前会话的删除入口。桌面悬停/键盘聚焦时显示操作菜单按钮，窄屏和触屏保持可见。
- 确认窗口显示目标名称，说明消息与关联的未入库候选会从工作数据库删除，默认聚焦“取消”，并提示先导出有价值内容。目前没有回收站或恢复接口。
- 只有确认删除后才发送 Owner 认证的同源 DELETE；不添加仅在页面隐藏的假删除。服务端原有并发租约和外键级联规则保持不变，无须数据库迁移。
- 删除非当前对话保留当前阅读、候选和输入草稿；删除当前对话返回新对话视图。取消不发送 DELETE；服务器拒绝或响应不明确时保留内容并要求核对，不宣称删除成功。
- 最小来源指针只保留溯源引用，不包含聊天正文，不作为已删除对话的记忆使用。独立审计、实际调用用量、公开文章及其 Git 历史不随会话删除。
- 自动私人候选保存已上线；**候选审阅后写入 GitHub、创建 PR、批准合并与正式入库尚未上线**。删除未入库候选会失去这部分草稿，不能将生成候选误认为已发布知识。


## 侧栏对话操作

每条会话的“⋯”菜单统一提供置顶/取消置顶、重命名和删除。列表按“置顶”“最近对话”分组，采用单行标题与选中背景，完整标题保留在工具提示和可访问名称中。菜单支持方向键、Home/End、Escape、Tab、外部点击关闭及焦点返回；进入改名或删除弹窗时由原生 dialog 管理焦点。

置顶使用 `sessions.summary_json.pinned` 布尔值，缺失或历史非布尔值视为未置顶，和 `title` 一样是私有展示元数据，不进入模型输入。PATCH 只允许 title/pinned，并使用 `json_patch` 原子保留其他对象键；旧会话无需迁移。列表先在数据库按置顶排序，再按更新时间和稳定 ID 排序、分页，因此分页之外的置顶会话也能出现在顶部。修改其他会话时不切换当前阅读、消息和输入草稿，不调用模型。
